## 1. What the app is for (from our existing domain work)
- The home screen candidate (Pepper's design thread, `family-environment/2026-11-11/costa-domain-audit.md` §6):
  1. **Tide curve** with the next low and high and a now marker. It decides reef and tide-pool timing.
  2. **Wave energy compared to this week** (calm, typical or big against the week's quartiles; never a "safe" score). It decides boogie boards or a lesson versus a sand day.
  3. **Sun and heat window**: sunrise, plus when UV and WBGT get hard. It decides beach hours for the boys.
- Cut from the home screen: rain (Dec–Mar is the dry season), wind and sunset. They can sit on a detail screen.
- **Hard rules:**
  - No swim-safe claims. The flag on the beach overrides the app.
  - Label every number: *predicted* (tides), *model forecast* (waves and weather), *computed* (WBGT, energy) or *official notice* (IMN).
  - Show each block's fetch time.
- Existing code to reuse:
  - `family-wx/fetch_cr_swell.py`: energy kJ = ρg²H²T²/(16π)/1000 from Open-Meteo swell height and period.
  - `visual-lab/2026-11-11/work/compute.py`: Liljegren WBGT, venv `/workspace/.venvs/heatclock-wbgt`.
  - The week-quartile logic in `family-environment/2026-11-11/this-week-sources/build_this_week.py`.

## 3. Backend options

| | (a) No server: the app fetches on open | (b) Scheduled job → one JSON file (**recommended**) | (c) Morning AI routine → server |
|---|---|---|---|
| How | The phone calls Open-Meteo (Marine and Forecast) and the IMN RSS directly. One year of NOAA tide predictions ships in the app bundle; at about 330 KB raw it's tiny, and gets refreshed with each app update. WBGT, energy and quartiles are computed in Swift. | A GitHub Actions cron (about 04:17 and 05:17 CR time; CR is UTC−6) runs our existing Python. It fetches Open-Meteo, NOAA and IMN, computes WBGT, energy and week quartiles, validates, and publishes `conditions.json` (plus `history/` for the last good file) to GitHub Pages. The app downloads one small file and caches it. | (b) plus a Grok Bot morning routine that reads the no-feed sources (CoopeGuanacaste page, AyA, maybe the IMN road PDF), writes structured JSON with source links and times, and commits it alongside (b)'s file. |
| Hosting | none | GitHub (Sean's account) Actions + Pages. A Cloudflare Worker cron is the alternative if Open-Meteo throttles GitHub's shared IPs. | the same as (b), plus a bot routine |
| Monthly cost | $0 (Apple Developer account already exists for Spike) | $0. A daily job of about 1 min uses a sliver of GitHub Free's included compute ($12/mo value, per GitHub docs). Pages on a public data repo is free. | $0 hosting, plus Grok Bot plan usage every morning |
| Keys | none | none for the data. One GitHub deploy token for the job (Actions' built-in `GITHUB_TOKEN`). | the same, plus the bot needs a push credential to the data repo |
| Failure behaviour | Each block shows its own fetch time. If a call fails, it shows the last cached value with "as of …". Logic is duplicated in Swift. | The job validates (enough hours, sane ranges, tide extremes present) and **never overwrites a good file with a bad one**. The JSON carries `generated_at` and per-source `fetched_at`. The app shows "as of 5:17 AM" and turns amber after 30 h. GitHub notes the schedule "can be delayed… some queued jobs may be dropped", hence two runs. | AI output can be wrong or partial. Each item needs a source link, quote and time, plus "unverified" styling. More moving parts can break silently, so it needs a health check. |
| Offline in CR | Tides always work (bundled). Waves and weather show the last successful fetch only. | The best fit: one file cached at breakfast, readable all day offline. Tides are bundled as a backup. | the same as (b) |
| Effort | The app is heavier: porting WBGT and quartiles to Swift needs tests. No backend. | The app is simpler (render and cache). The job is about half a day, mostly reusing our scripts. | (b) plus the routine and parser upkeep; pages change without notice |
| Risks | Open-Meteo field or model changes land in the app, and fixing them needs a TestFlight build. | GitHub disables scheduled workflows in a **public** repo after 60 days without repo activity. The daily data commit should count as activity; check that in week 1. | the brittleness of scraping JS sites; unconfirmed whether Sámara is even in the CoopeGuanacaste/AyA listings |

**Recommendation: (b).**
- It keeps the fiddly science (WBGT, energy, quartiles) in the Python we've already checked, gives the app one cacheable file for spotty CR signal, and fixes data bugs without a new TestFlight build.
- Also bundle the year of NOAA tides in the app, so the tide curve never depends on the server.
- No AI is needed for the home screen. Add (c) later only if Sean wants power or water notices, and only after confirming Sámara's utility, and that its notices actually appear on those pages.
